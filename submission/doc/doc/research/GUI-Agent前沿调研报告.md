# GUI Agent 前沿调研报告

本报告用于解释：为什么本项目不是简单“换一个更大的 VLM”，而是采用“VLM 看图 + 本地规则校验 + 历史记忆”的混合方案。

## 调研结论

近两年的手机/电脑 GUI Agent 方案有一个共同点：模型负责理解截图和目标控件，但执行前后会有工程层保护。只让模型直接输出最终动作，容易出现坐标点偏、重复点击、输入后继续乱点、提前完成等问题。

对本项目最有价值的结论有四条：

1. **视觉定位是核心能力**  
   Qwen2.5-VL、Qwen3-VL、SeeClick、OS-Atlas、UI-TARS 都强调 GUI grounding，也就是“看到一个按钮说明后，能在截图上点准位置”。这说明我们选用千问 VLM 是合理的，但模型输出仍需要坐标裁剪和动作校验。

2. **动作空间必须统一**  
   UI-TARS 和 AppAgent 都把复杂手机操作收敛成点击、输入、滑动、返回等少数动作。本赛题也只允许 `CLICK / TYPE / SCROLL / OPEN / COMPLETE`，所以我们的 `OutputParser + Validator` 是必要模块。

3. **长任务需要记忆和阶段判断**  
   Mobile-Agent 会先感知界面，再拆解任务并逐步执行；AppAgent 会通过探索或演示形成可复用知识。对应到本项目，就是 `Memory` 记录最近动作、已输入文本、已打开 App，并根据任务类型决定是否可以完成。

4. **隐藏集会考泛化，不会只考公开样例**  
   AndroidWorld 的设计强调动态任务、自然语言多样表达和程序化检查。榜单日志也验证了这一点：公开 11/11 不代表隐藏集稳定。后续优化必须按“任务类型”抽象规则，而不是按单个公开用例硬背坐标。

## 落到本项目的优化方向

第一，保留官方 API 调用入口。比赛要求通过 `BaseAgent._call_api()` 使用统一配置，所以代码不能自己新建百炼客户端，也不能写死模型名和密钥。调试时可以用百炼的 `qwen3-vl-plus`，提交时必须交给主办方的 `EVAL_API_*`。

第二，继续让 VLM 处理不确定页面。比如隐藏集截图里按钮位置、弹窗、入口文字可能变化，这类问题不适合全靠固定模板。

第三，给高风险动作加本地保护。榜单 51.72 分日志显示，失败集中在“写完评价后”的最后一步：有的场景需要点右下角发送，有的场景输入完就算完成。这个判断让模型每次猜很不稳，所以已经落到 `validator.py`：

```text
刚输入长评价文本 + 京东/拼多多/淘宝 -> COMPLETE
刚输入长评价文本 + 抖音/爱奇艺/视频评论 -> 点击右下发送
刚输入长评价文本 + 未知 App + 底部中间点击 -> COMPLETE
刚输入长评价文本 + 未知 App + 左下/右下点击 -> 纠正到右下发送
刚输入长评价文本 + 模型想滚动 -> 优先点右下发送
```

第四，把 Prompt 从“只描述动作格式”升级为“告诉模型流程区别”。现在 Prompt 已明确区分电商评价和社交/视频评论，减少模型把两类任务混在一起。

## 后续可继续做的事

如果再次提交后分数仍停留在 50 多分，下一步不要先大改模型，而是继续收集完整失败日志。每个失败日志至少要包含：用例名、用户任务、每一步输出、期望动作类型、失败原因。

有了完整日志后，按以下优先级优化：

1. **输入后收尾类**：`TYPE` 后到底是 `CLICK` 还是 `COMPLETE`。
2. **首屏入口类**：模型输出 `SCROLL` 但评测期望 `CLICK`。
3. **搜索确认类**：输入搜索词后应该点键盘搜索、搜索按钮还是候选词。
4. **详情页完成类**：播放、收藏、点赞、下载之后何时 `COMPLETE`。
5. **弹窗处理类**：广告、权限、青少年模式、升级弹窗的关闭/允许策略。
