# 论文阅读笔记

## Mobile-Agent

Mobile-Agent 的关键思想是“先看清界面，再做计划，再执行动作”。它用视觉感知工具识别文字和图标位置，然后让大模型根据这些视觉上下文分解任务。对我们来说，无法额外训练或部署感知模型，但可以借鉴它的流程，把任务拆成阶段，并用 `Memory` 记录每一步。

本项目对应实现：

```text
截图理解：交给 VLM
任务槽位：task_parser.py
历史记忆：memory.py
动作校验：validator.py
高置信流程：policy.py
```

## AppAgent

AppAgent 强调简化动作空间，并通过探索或人类演示形成知识。它不是每一步都从零开始猜，而是把 App 的操作经验沉淀下来。

本项目对应实现：

```text
官方动作空间：CLICK / TYPE / SCROLL / OPEN / COMPLETE
公开稳定流程：写在 RulePolicy 中
隐藏失败经验：抽象成任务类型规则，写进 Validator
```

这解释了为什么我们要补“评价输入后收尾规则”。它不是硬背某个隐藏用例，而是把“写评价”这个任务类型沉淀成经验。

## SeeClick 与 OS-Atlas

这两类工作都说明 GUI Agent 的难点不是输出文本，而是“按自然语言目标点准 UI 控件”。如果模型把发送按钮看成左下角或底部中间，评测器会直接失败。

本项目对应实现：

```text
坐标裁剪：clamp_point
重复点击保护：repeated_click_count
评价后点击纠偏：_post_review_action
首屏评价入口保护：_looks_like_review_task
```

## UI-TARS

UI-TARS 的启发是三件事：统一动作建模、长任务中的阶段性推理、失败后的反思修正。我们不能训练 UI-TARS，但可以用轻量工程方式模拟一部分。

本项目对应实现：

```text
统一动作：OutputParser 解析各种模型格式，再统一成官方 AgentOutput
阶段性推理：Prompt 要求模型判断桌面、首页、搜索页、结果页、表单页、完成页
反思修正：Validator 根据历史动作修正不合理输出
```

## AndroidWorld

AndroidWorld 的重要启发是：公开样例通过率不等于真实泛化能力。动态任务会换 App、换说法、换参数、换页面状态。

本项目后续优化原则：

```text
不要只按用例名补坐标
优先抽象任务类型
每次补规则后跑公开回归
隐藏日志按失败动作分类
```

这也是本轮从 51.72 分日志中抽象“评价输入后收尾”的原因。
