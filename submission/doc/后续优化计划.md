## 1. 这次日志暴露的问题

本次榜单得分为 51.72/100，说明当前方案已经能覆盖一部分公开和隐藏任务，但对新的电商评价、内容评论类任务还不够稳。

从日志里能明确看到三类失败：

```text
douyin_lp_scene_0：
已经输入“手机支架很好用...”这类长评价文本后，模型输出 SCROLL。
评测期望 CLICK，说明输入后应该点发送、发布或提交区域。

jingdong_lp_scene_1：

评测期望 CLICK，说明当前首屏已经有“评价 / 去评价 / 晒单”等入口，模型不应该先滑动。

```

这些失败不是格式错误，而是“模型对评价流程的结束条件和按钮位置不稳定”。

## 2. 本轮已经完成的优化

本轮没有继续硬背某一个隐藏用例，而是抽象成三条通用规则：

```text
1. 输入长评价文本后，如果模型想 SCROLL，则改成点击右下角发送/发布区域。
2. 输入长评价文本后，如果模型想点击屏幕中间的泛化区域，且任务没有明确要求发布/发送/提交，则改成 COMPLETE。
3. 评价/评论/晒单类任务在前两步如果模型想 SCROLL，则改成点击右侧中部的评价入口区域。
```

同时更新了 Prompt，让模型在电商评价、晒单、评论类任务中优先找：

```text
评价
去评价
评价晒单
写评价
发表评论
发布
发送
提交
```

而不是看到列表就先滑动。

## 4. 下一轮如果分数还不高，怎么继续做

下一轮最需要的是完整失败日志。当前日志只截到了前三个隐藏失败，缺少后面失败用例的名称、动作和失败步骤，所以只能针对这三类问题优化。

继续优化时按这个顺序做：

```text
第一步：收集完整榜单日志，至少包含所有 FAIL 用例名、每一步 Agent Output、期望动作类型。
第二步：按用例名前缀归类，比如 douyin_lp、jingdong_lp、pinduoduo_sl。
第三步：每类只抽象“任务类型规则”，不要按单个坐标硬背。
第四步：先补 Validator 的动作后处理规则，再补 Prompt，最后才补固定流程模板。
第五步：每次改完都跑公开 offline 回归，确保 11/11 不掉。
第六步：重新打包 submission.zip，再上传看隐藏榜单变化。
```

优先关注的隐藏任务类型：

```text
电商评价类：京东、拼多多、抖音商城、淘宝等。
评论发布类：短视频、长视频、内容社区。
首屏入口类：模型输出 SCROLL 但评测期望 CLICK。
输入后结束类：输入完成后评测期望 COMPLETE，而模型继续点击。
输入后提交类：输入完成后评测期望 CLICK，而模型滚动或完成。
```

## 5. 当前版本的核心策略

当前版本不是单纯靠 VLM，也不是完全靠固定模板，而是：

```text
确定流程：规则保底
不确定页面：VLM 看图
模型输出：Parser 容错解析
危险动作：Validator 修正
```

通俗讲，就是“模型负责看图，程序负责把容易错的地方兜住”。
